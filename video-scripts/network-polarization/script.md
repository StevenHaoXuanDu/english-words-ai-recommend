## 视觉规范

- **背景**：纯黑 `#000000`，全片不出现其他底色。
- **横轴就是看法**：x = 0 到 1 映射到画面横向 160–1760 px。矩形的位置和颜色表示同一件事，所以看法靠近时，矩形会同时在空间上滑到一起、颜色也随之融合。
- **矩形**：10 × 28 px，起始间距 16 px。颜色在 OKLab 中插值：x = 0 青 `#5BB5A8` → x = 0.5 金 `#E8C066` → x = 1 朱 `#D4573B`。外发光用同色，模糊 12 px，不透明度 35%。共识的位置正好是 x = 0.50，所以共识色就是纯金。
- **色块**：看法几乎相同（相差 < 0.005）的矩形，在该 x 处向上打包成紧凑方阵，方阵高度对应人数。50 人 = 5 列 × 10 行，100 人 = 10 × 10。
- **括号**：两条 1 px 金线加顶部短横，宽度 = 2ε × 1600 px（ε = 0.20 时 640 px，0.30 时 960 px，0.40 时 1280 px）。括号以当前矩形为中心，碰到两端就截断，括号外的矩形压暗到 20%。
- **字幕**：思源宋体 Medium 48 px，`#F3E9D2`，放在画面下三分之一处。逐字快速浮现（每字上浮 8 px 并淡入，整句约 0.3 s 内出齐），离场时整句 0.22 s 淡出并轻微虚化。每句完整可读的时间不少于 0.45 s + 字数 / 8 s，且不少于 1.2 s。
- **底部注释**：IBM Plex Mono（或 JetBrains Mono）18 px，全大写，字距 0.15em，金色 45% 不透明度，距底边 48 px。
- **每一轮**：用 0.6–1.0 s 的补间表现一次同步更新：快起、长落，x 方向从不过冲；先横向靠拢，再向上堆叠。每轮开始时一道扫描光自上而下扫过整排（所有 x 同时被扫到，因为更新是同步的），配一声玻璃质感的 tick。

## 动效层

全片在上述画面之上叠一层持续的、克制的动效，让静止处也在呼吸。规则：装饰性的动效只改亮度、光晕和 y 方向的微小位移，从不改变任何矩形在横轴上的位置；屏幕上的每个数字都来自 `hk_sim.py`。

- **背景**：纯黑底上三层视差的金色微尘缓慢上浮、闪烁，随镜头运动产生视差；一层极暗的暖色光雾缓慢漂移，数据附近带一点它们自己颜色的散射光；四角压暗。光雾经抖动处理，避免色带。全部元素都远暗于矩形。
- **看法轴**：行下方一条极淡的 0–1 横轴，每 0.1 一个刻度（0、0.5、1 标数），开场随矩形一起由中间向两端画出，此后轻微呼吸；它和矩形用同一个镜头变换，刻度始终对准看法。每轮更新时轴亮一下。
- **数据的生命感**：静止时矩形有 ±1.5 px 的纵向呼吸波、一道缓慢扫过的微光和极轻的逐个闪烁。括号停住时，一圈「倾听」光波从括号中心的矩形向括号边缘一遍遍扩散，只经过括号内的成员。桥的两条细线上有光点往返。移动中的矩形拖一段很短的残影。
- **镜头**：整个数据平面有极慢的推拉与漂浮（最多约 ±0.8%），矩形、括号、刻度一起动，相对位置不变。
- **转场**：第二章推近；第三章开头一道光束扫过整排；第四章是倒放；第五章是推镜冲进黑缝；第六章是光束擦除转场。
- **重点时刻**：S10 共识、S13 定局、S16 拉黑熄灭、S20 合拢，各配一次克制的光晕、地面波纹或火花。
- **文字**：字幕逐字浮现；底部注释像打字一样出现，带闪烁的方块光标；字卡逐字对焦、字距收拢；每章开头左上角出现约 2 秒的章节标签（如「01 · 村子 / THE VILLAGE」，带一条画出的细线）。
- **数据读数**：实验与桥的段落右上角有一行低调的读数，如 `ROUND 003 · ε 0.20 · GROUPS 9 · SPREAD 0.53`，以及每轮 SPREAD 的小折线（实验二时实验一的折线留作暗色对照）。数值逐轮取自模拟的状态，显示的是正在进入的那一轮，与底部注释一致。

## 数据来源

运行 `python3 hk_sim.py` 就能打印下表全部数字；加 `--json frames.json` 会导出每一轮 100 个矩形的位置，可以直接驱动动画。

| 屏幕上的数字 | 出处 |
|---|---|
| 实验一 SPREAD 1.00 → 0.71 → 0.46 → 0.29 → 0，第 4 轮共识，x = 0.50 | ε = 0.30 等距起点模拟 |
| 实验二 GROUPS 9 → 8 → 4 → 2 → 2（第 3–7 轮），第 7 轮是最后一次挪动（0.005），50 \| 50，x ≈ 0.31 / 0.69，GAP 0.39 | ε = 0.20 等距起点模拟；相距 < 0.02 记为同一组 |
| 桥：第 1 轮走到 x = 0.50，离两边各 0.19，第 36 轮合并 | 从实验二终态出发，左组 1 人 ε 改为 0.40，其余 99 人仍为 0.20 |
| GAP ≤ 2ε 条件 | 由模型规则直接推出：桥必须同时落在两边各自的 ε 范围内 |

**S21「并不总能成功」的依据**（片中不出现，`python3 hk_sim.py --random` 可复现）：300 组随机起点中，ε = 0.30 有 299 组达成共识；ε = 0.20 有 273 组裂成两块，同样只放一座桥（ε = 0.40），在这 273 组里只有 83 组合上了。片中的等距起点恰好是能合上的那一类，这正是 S21 这句旁白要说清楚的。

## 制作备注

1. **「挪到平均值」与「靠一点」**：原版 HK 模型每轮直接跳到邻居的平均值，片中用补间让它看起来像缓慢靠近。如果想严格表现「每轮只靠一点」（x ← x + μ·(mean − x)，μ < 1），那是另一个变体，轮数和簇的位置都会变，必须重跑，不能沿用片中的数字。两人一组、每次只靠近一点的经典模型是 Deffuant 等人（2000）。
2. **轮数不是时间**：「7 轮」「36 轮」是模型里的迭代次数，不对应现实中的天数或年数。旁白里没有把它说成时间，剪辑时也请不要配上日期之类的暗示。
3. **第五章是比喻，不是测量**：片中没有任何关于平台、算法影响大小的数据，S16 的括号也刻意不标数值。如果后期想加实证研究，需要单独核实来源，并在注释里标明。
